# 语义时间窗与声画同步

只在最终口播已确认、需要生成旁白时码、分镜、MG 或字幕时读取。目标是让声音成为唯一主时钟，让每个重要词都能在正确时刻触发可理解的画面变化。

## 正确顺序

1. 锁定观众实际会听到的口播稿版本。
2. 生成或取得最终旁白母本，保存哈希和稿音对应关系。
3. 整理异常长静音并选择最终速度；此后得到的音频才是主时钟。
4. 用 forced alignment、ASR 发声锚点或完整语义句真实时长，把定稿文字反标到最终音频。
5. 按意义划分语义时间窗，在窗内标记短语/关键词锚点。
6. 先写声画合同，再设计 MG、截图和音效。
7. 使用同一时间轴逐帧渲染，输出调试版和发布版。

禁止在最终音频出现前按字数估时。ASR 只提供时间，发布文字必须回到定稿纠错；字幕切分不得反过来拆碎自然口播。

## 五层时间结构

1. **最终音频主时钟**：总时长、最终速度、停顿编辑映射与音频哈希。
2. **口播句 `voiceCues`**：完整语义句的实际起止时间和定稿文字。
3. **语义窗 `semanticWindows`**：一个完整问题、动作链、证据或判断，可以跨一句，也可以把长句拆成多个可理解阶段；时长由意义决定，不机械等长。
4. **发声锚点 `anchors`**：观众听到某个短语时触发的动作、状态或证据切换。关键词必须能在对应口播句中找到，时间必须位于语义窗内。
5. **字幕 `subtitleCues`**：来自同一对齐结果，按自然语义和最多两行重新分条；不是另一套独立估时。

词级时间戳不是所有画面都必须使用。只在点击、数字跳变、字段组合、局部聚焦等需要精确触发的地方保留；其他时间让完成态稳定停留，避免持续无意义运动。

## 语义窗声画合同

每个语义窗必须回答：

- `viewerNeed`：观众此刻需要弄明白什么；
- `spokenClaim`：这段旁白实际说了什么；
- `objects`：画面中承担信息的对象，不写抽象装饰；
- `action`：对象发生的可见动作；
- `startState`：动作前是什么状态；
- `endState`：动作后留下什么完整可读状态；
- `resultEvidence`：用什么结果、截图字段或状态证明动作完成；
- `anchors`：哪些实际发声短语触发哪些视觉事件；
- `holdUntil`：完成态至少保持到哪个时间，确保观众看清；
- `coverageStatus`：只有全部字段和证据闭合后才能是 `covered`。

画面只承担对象、动作、状态变化和结果证据。不能把整段口播换一种字号重新显示；屏幕文字只能是关键词、对象标签、数值、状态或帮助理解关系的短句。

## 锚点设计

每个重要动作至少绑定一个锚点：

```json
{
  "id": "rename-input-drag",
  "time": 13.31,
  "phrase": "把文件直接拖进去",
  "event": "file-drag-to-chat",
  "target": "workbuddy-input",
  "resultState": "文件已进入对话",
  "holdUntil": 15.1
}
```

- `time` 对齐短语真实起声点，不对齐字幕框出现的估计位置。
- 动作可以略早于词尾完成，但不能在观众听到动作前提前展示结果。
- 结果状态至少保持到下一个锚点，或保持到观众已经获得足够阅读时间。
- 同一句连续包含多个动作时分别打锚点；不能让整句只触发一次泛化入场。
- 没有关键动作的判断句，可以用对比关系、风险分支或证据聚焦承接，不强行制造点击。

## 官网截图节奏

每张官网图按需要经历四个阶段：

1. `context`：先让观众知道这是哪个页面或哪一步；
2. `focus`：说到按钮、字段、表格行或结果时再聚焦；
3. `action`：用鼠标、输入、框选或状态变化表现发生了什么；
4. `verify`：保留足够上下文，让观众确认结果和未处理范围。

局部放大必须绑定正在发声的具体短语，并记录来源、区域与证明主张。一个结果需要同时看成功项与排除范围时，不能裁掉其中一边。官网没有配图时，用明确标注的 MG 对象和状态表达文字步骤，不伪造产品界面。

证据对象还要记录 `displayMode` 和 `sourceScope`：单图使用 `single`，两张文字型截图默认使用 `stacked`，三张及以上使用 `anchor-sequence`；公开官网素材标为 `official-public`。两张图不得退化成左右小窗，三张以上不得按图片数平均轮播或做四宫格。公开官网素材不自动遮挡；只有实际混入非公开信息时才建立遮挡区域。

## 统一重映射

音频一旦删停顿、替换句子或变速，所有依赖时间必须通过同一映射重算：

- 口播句；
- 语义窗；
- 发声锚点；
- 字幕；
- 截图切换和聚焦；
- 音效；
- 片尾稳定停留。

不得只替换音轨、只移动字幕或手工拖几个场景。稿件内容改变时旧音频、旧对齐和旧时间轴全部失效；仅保持音高的整体变速也必须重新映射并抽听专有名词、数字和句尾。

## 确定性渲染

视觉工程优先暴露 `renderAt(t)`。每一帧使用 `frameIndex / fps` 得到绝对时间，再从同一时间轴计算当前场景、语义窗、锚点进度和字幕。不要依赖 CSS 墙钟动画、实时录屏或页面加载后的相对计时。

对同一输入重复渲染时，每个动作必须落在同一帧。转场期间至少保留一个完整可读状态；新状态可识别后再移除旧状态。

语义窗之间若存在录音停顿或对齐空隙，时间轴必须声明 `gapPolicy`，默认保持上一窗的完成态，不能把“当前没有命中窗口”回退到片尾、片头或空白页。相邻窗采用有重叠的交叉切换或对象连续变形；同一截图跨窗时优先继承镜头状态。短于约 1.35 秒的窗默认设为 `overlay-bridge`，叠加在前一完整状态上承接，不单独硬切一整页。

每张截图的出现时间由它自己的 `narrationAnchor` 决定。禁止用“场景时长 ÷ 图片数量”选择当前截图。完整图到聚焦图使用连续插值；新的证据图在约 0.28–0.62 秒内变得可识别后，旧图才退出。

## 调试版与终验

正式版之前输出调试层，至少显示：

- 绝对时间码；
- 当前语义窗 ID；
- 当前/下一锚点；
- 当前口播句 ID；
- 截图证据来源编号（若有）。

按以下位置抽查：开头钩子、每个语义窗起点/中点/终点、每个锚点前后、每次截图聚焦、最快一句、所有中英混排、结果数字和片尾 CTA。然后以 1× 速度完整播放一次；调试层通过后再移除并重渲染发布版。

以下任一项出现即失败：

- 旁白已经进入下一步，画面仍停在上一步；
- 结果在动作词说出前提前出现；
- 一个长窗只有一次入场，后续没有语义变化；
- 截图在错误字段上放大，或裁掉结论所需上下文；
- 字幕、MG、截图和音效来自不同时间源；
- 音频改动后只局部手调时间；
- 调试版或 1× 完整播放尚未完成就宣称通过。

运行 `scripts/validate_av_timeline.py <timeline.json>` 做结构拦截。自动检查不能替代 1× 完整观看。
