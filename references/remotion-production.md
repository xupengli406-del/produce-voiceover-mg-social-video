# Remotion 画面制作层

新建 MG 工程、迁移渲染器或修改动画组件时读取。它补充画面实现，不替换口播、证据、音频、导演、封面和逐帧终验。依然只有一个主智能体；读取官方专项文档不等于启动子智能体。

## 1. 接入范围与版本

- 新工程默认使用 `assets/remotion-template/`，保留已有确定性工程，不自动迁移或重渲染已认可的长片。
- 本模板按 Remotion `4.0.520` 实测，React 与所有 Remotion 包精确锁定；保留 `pnpm-lock.yaml`。升级依赖后重新跑组件测试和实际渲染，不用 `latest` 绕过验证。
- 官方知识入口：[Agent Skills](https://www.remotion.dev/docs/ai/skills)、[上游仓库](https://github.com/remotion-dev/skills)。按当前问题读取对应章节，不复制整套上游手册到主 Skill；不要求额外安装另一个 Skill 才能使用本模板。
- 借鉴：[帧驱动](https://www.remotion.dev/docs/the-fundamentals)、[文字测量](https://www.remotion.dev/docs/layout-utils)、[标注](https://www.remotion.dev/docs/text-highlights)、[Studio 编辑](https://www.remotion.dev/docs/studio/interactivity)。采用自有几何组件落实更严格的截图避让，而不是照抄黄色荧光条或固定圆圈。
- 运行环境需 Node.js、包管理器和兼容的 Chromium。字体由运行配置选择；默认 PingFang SC，不打包系统字体。其他系统显式选择已授权且可用的中文字体，重新测量和验收，禁止悄悄回退字体。使用与部署须遵循 [Remotion 当前许可](https://www.remotion.dev/license)，不把仓库可见等同于所有商业场景免费。

## 2. 唯一时间轴与派生产物

`work/timeline.json` 继续是唯一可编辑时码源。保留原有全部 `voiceCues`、`semanticWindows`、`anchors`、`visualContract`、`directorPlan`、`assets`、`subtitleCues`，只在语义窗内补充 `render`。不得为了接入渲染器删掉事实与声画合同。

```json
{
  "render": {
    "kind": "evidence",
    "title": "改了哪些，一眼看清",
    "anchorIds": ["已有真实发声锚点ID"],
    "assetIds": ["素材账本中的ID"],
    "source": {"w": 1600, "h": 900},
    "targets": [{"x": 120, "y": 300, "w": 800, "h": 72}],
    "avoidRects": [{"x": 100, "y": 200, "w": 900, "h": 70}]
  }
}
```

- 所有 `targets`、`avoidRects` 坐标均来自原始图片像素，`source` 必须等于真实图片尺寸；不要把屏幕坐标误当原图坐标。无框可测的纯图片需要先人工或 OCR 定位，再按原图复核，不能假定组件自动理解截图。
- `frameAt(seconds,fps)` 统一转换绝对时码；不要对各段长度独立四舍五入后累加。当前场景和字幕用同一帧时钟。
- 本模板在根组件取全局帧，场内动作只通过指定锚点计算进度。改用 `Sequence` 时必须明确全局帧和局部帧的转换，不能将全局锚点直接减局部帧。
- 时码空隙声明 `gapPolicy: hold-previous`，保持前窗完成态。缺失开头、重叠窗口、未知动作、未知素材或未知锚点必须报错，不回退片尾、空白或通用模板。
- 默认不使用会缩短总时长的重叠转场。增加 `TransitionSeries` 时须明确重叠预算，不能让后续锚点提前；两张文字截图禁止整体交叉叠化。短桥接窗按原同步规范编写专门场景，不强行套本模板的整屏切换。
- `prepared-props.json` 是带来源哈希的编译结果，不是新的编辑入口。每次改原声、素材、字幕、布局或时码，重新准备并重新记录项目状态；修改画面代码同样使旧 render/audit/delivery 失效。

## 3. 组件不是固定分镜

模板提供五种可扩展的动作示例与共用基础组件，不声称覆盖所有题材：

| 组件/动作 | 用途 | 不能替代的导演判断 |
| --- | --- | --- |
| `transfer` 文件进入工作区 | 对象移动、接收结果 | 输入入口、文件种类、动作是否真实 |
| `fields` 字段组合 | 从字段到统一命名结果 | 当前案例的真实规则和选择条件 |
| `evidence` 完整证据与目标标注 | 保留上下文、逐锚点切换标注 | 目标是否真的证明旁白 |
| `stacked` 上下全宽双证据 | 两图不挤成窄小缩略图 | 两图是否都需要、是否能读清 |
| `flow` 节点和有向接力 | 节点先可见、连接随后建立 | 正确因果、顺序与反馈 |

共同基础：`Text`、`EvidencePanel`、`SafeAnnotation`、`SafeArrow`、`LayoutAudit` 和纯函数时间/几何合同。

新语义不适合这五种时，新增场景组件并加测试，不改文案迁就模板。不把五种示例重新变成反复套用的五页 PPT。每窗仍先决定 `attentionTarget → visualBeat → payoff`；纯判断、风险选择、跨设备、生成情境或品牌首次识别应按本期需求扩展。生成图片仍遵守身份/证据/解释/氛围分层，只在能提升理解或情境感时取得，不因模板尚无图片而省略。

## 4. 从规范到可执行检查

### 文字与版式

- 字体加载后用真实字体、字号、字重测量；字幕默认 46px、最多两行，品牌及缩写不拆开。字号层级固定，超出时先按自然语义重新分条、重排或分场，绝不无限缩小。
- 当前布局明确分离标题、主画面和字幕区，字幕底部到 1920 画布边缘保留 160px。其他平台 UI 安全区更大时上移并复验，不能机械沿用固定数值。
- `LayoutAudit` 检查这些区域相互重叠及可测文字溢出，不能证明图像内文字、透明图标可见像素或所有内部子组件都没遮挡。新增图层必须登记范围；实际渲染帧和手机尺寸目检仍是硬门槛。

### 标注与箭头

- 原图目标经 `contain` 的缩放与留白映射到显示坐标，再按笔画宽度外扩。长句默认外框，不用从四角切入文字的扁椭圆。框尺寸每目标重算。
- 传入完整 `avoidRects`，不是只填被圈目标。空间不足直接报错，改构图/标注类型，不能关闭检查强行渲染。
- 箭头优先共同轴直线，再尝试一次折线；头部按末段方向计算，终点在节点外，路径和箭头宽度一起避障。多条箭头同屏还须把其他路径作为避让对象检查，不宣称单条路由检查涵盖所有互相交叉。
- 零进度及短于两倍线宽的路径不挂载，阻止孤立圆点。结果节点先可见，关系线再生长。
- 这些几何检查是保守拦截，不等同于最终可见像素零交叉证明。进入、半程、完成态都要看真实帧；截图自带遮挡仍需先修原素材呈现。

## 5. 制作和验证命令

```bash
python scripts/init_project.py <新项目目录> --title "主题" --renderer remotion
```

在生成的 `work/visual/remotion` 内安装锁定依赖并运行纯函数测试：

```bash
pnpm install --frozen-lockfile --ignore-scripts
pnpm test
pnpm studio
```

需要依赖构建脚本时先确认其用途，仅对所需包显式允许。不要修改系统包管理器或全局浏览器配置。已安装 Chrome 可通过 `REMOTION_BROWSER_EXECUTABLE` 环境变量指定，不写死机器路径。

完成口播、音频与原有三项时间轴/导演/素材校验后，给每窗编写 `render`，再运行：

```bash
python scripts/prepare_remotion.py <项目目录>
```

此步骤核对最终音频/素材哈希，复制所需媒体到渲染器的 `public/inputs`，生成派生 props。生产渲染在工程内运行：

```bash
node scripts/render.mjs <新的验收输出目录> prepared-props.json --video
```

输出实际边界/锚点帧、事件变化检查、重复帧确定性结果、视频与技术报告。每个目录禁止覆盖，修订后生成新目录并按清理规则处置旧版。全片帧之间有变化不等于变化正确落在目标上，主智能体必须复核对应目标。

不带 props 是独立组件诊断：

```bash
node scripts/render.mjs <新的诊断目录> --video
```

诊断使用 32 秒合成时码和合成示意图，没有旁白，不调用 TTS、不伪造官网实践；它验证代码，不通过口播、发声对齐或真人听感门槛。`technical-pass` 不等于 `audit approved`。

## 6. 实际回归与推广门槛

修改文字/圈注/箭头/窗口选择器后，先跑单元测试，包含故意错误的第三行字幕、压字标注、无路可走的箭头、未知锚点与非法时码；不能只有合法例子截图。

接着实际渲染：每个窗口边界前后至少三帧，每个锚点前、刚进入、中程、完成帧；检测缺失动作，重复渲染同一帧检查确定性。目检主对象、目标定位、字形、源图裁切和手机可读性。

这只让新渲染器具备工程使用条件。首次用于正式长片前，仍用已认可的同一份口播、真实音频和素材制作 30–60 秒标杆，与旧版比可读性、动作质量、同步、返工次数和耗时；未经实际对照，不宣称 Remotion 更快、更省 token 或成片自动更好。0–8 秒产品开头门槛、逐锚点十二类审核和完整 1× 听审一项不减。

## 7. Studio 和变更边界

Studio 能否拖动、改关键帧，取决于当前代码是否符合官方交互结构；本模板优先语义数据驱动，不承诺所有计算属性可直接拖动。需要可视化微调时对适合的元素暴露参数或交互组件，不把唯一时间轴拆成多份手写值。

Studio 的时间修改必须回写 `work/timeline.json` 后重编译；布局修改记录 visual 阶段并令下游失效。不得只保存浏览器里看起来正确的状态。对旧 Canvas 工程使用 `--renderer canvas-legacy` 必须显式选择并记录原因，旧模板仅兼容，不作为新工程自动降级通道。
