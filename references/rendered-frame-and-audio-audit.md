# 逐锚点画面与声音终审

长片、多案例、官网证据讲解或创作者已指出“遮挡、裁切、卡顿、错位”时必须读取。这是实际成片验收规则，不是代码风格建议。

## 一、审核单位

不再以“一个场景”或“一分钟”作为最小验收单位。每个完整语义窗都必须检查：

1. 入场后的第一个可识别状态；
2. 每个发声锚点前约 `0.10–0.14s` 与后约 `0.14–0.22s`；
3. 每次截图、裁切区、标注目标或结果状态切换的前、中、后三帧；
4. 语义窗退场前的完整态；
5. 与下一窗边界前后的连续帧。

不得只看场景起点、中点和终点。错页闪帧、双曝光、空底板和元素晚到通常只出现在锚点附近。

## 二、官网证据的可读与指向合同

每个证据状态必须记录：

- `source`：原图或实机截图；
- `contextRect`：先用来定位页面的完整区域；
- `focusRect`：当前句真正要看的按钮、字段、表格行或结果；
- `narrationAnchor`：标注进入的真实发声点；
- `annotation`：红圈、短箭头、下划线或光标中的一种；
- `targetMeaning`：这个位置证明什么；
- `resultState`：动作后必须保留的完整状态；
- `holdUntil`：保持到观众足够读完的时间。

硬性规则：

- 先全局定位，再局部聚焦。第一帧就过度放大、只剩残句或一块空白，直接失败。
- 裁切区内默认使用 `contain`。`cover` 只能在已证明不会二次截掉字段的情况下使用。
- 任何正在被引用的句子必须保留句首、句尾和必要上下文；表格必须保留表头与当前行；UI 必须保留当前操作点的页面身份。
- 一个发声锚点只能有一个主标注目标。旁白讲到哪个字段，红圈或短箭头才移到哪里。
- 禁止使用跨越整张证据的黄色、绿色或灰色长条作为“高亮”。没有明确目标坐标和发声锚点的遮罩一律视为无意义装饰。
- 证据标注不得盖住它要证明的文字。红圈沿目标外边缘走，箭头停在边缘外，不用实心色块压住原文。
- 官网只提供一张终态图时，可以圈出它提供的入口或结果，但不得伪造点击后界面变化。
- 文字型官网图在约 `360px` 宽预览中仍应读清当前字段。一屏放不下就分步接力，不得用左右小窗或缩略图完成数量任务。

## 三、布局、碰撞与完成态

- 标题、证据、MG 主体和字幕使用四个不重叠安全区。任何图片变形、上移或放大后都必须重新检查边界，不能只验证初始坐标。
- 图标与文字必须实测可见像素外接框。同一卡片内保留明确间距；不得用“代码写了居中”代替成片抽帧。
- 背景、边框、图标、文字和状态必须作为一个组件入场。禁止先出现无字底板、极淡空壳，再过几秒补字。
- 入场动画通常在锚点起声后 `0.20–0.38s` 内达到可读态。如果信息到达时旁白已经进入下一层，直接判为声画错位。
- 密集文字截图不得交叉叠化。用硬切、遮罩推移或共享对象接力；上一张先完整离场，下一张再进入。
- 相邻语义窗如果主图、裁切和结果状态都没变，必须合并窗口或重做第二窗的动作。不得仅重置入场动画来假装切换。
- 镜头结束时必须留下完整可读态。信息只在最后 `0.3–0.5s` 完全出现，或出现后立即截止，视为未交付。

## 四、MG 事件必须真正发生

对每个必须可见的锚点事件，比较锚点前后帧：

- 必须出现对象位置、状态、高亮、连线或结果中的至少一项可识别变化；
- 变化不能只是透明度从 `0` 到“几乎看不见”；
- 动作必须落在声画合同中的 `target` 上；
- 锚点后的结果必须保持到 `holdUntil`，不得中途消失。

应该出现的 MG 没出现、只出现底板或在下一句才出现，都是阻断级失败。

## 五、声音接缝与重抽规则

- 不得在 PCM 中直接删除一段后拼接两个非零样本。即使切点落在静音，也要使用零点切割、短淡入淡出或等功率交叉淡化。
- 删除长停顿时，保留语义气口；不要把每个标点都压成同一时长。连续两个约 `0.35–0.45s` 的停顿也可能比单个长停顿更机械。
- 合成音出现黏字、重复音节、异常口音、吞字、情绪断裂或句内机械卡顿时，优先重新生成完整语义句或完整语气单元，不用半句拼接修声。
- 如果原音色当前无法再生成，可回到该音色已授权的原始合成文件做无损接缝修复；不得悄悄替换其他音色。交付时记录降级原因。
- ASR 失配只能作为耳听候选，不能单独判定读错；最终结论必须来自 `1×` 耳机听审。
- 任何重抽、替换、删停顿或变速都会让旧时码失效。字幕、语义窗、锚点、证据切换和音效必须由同一映射重算。
- 片尾最后一句说完后，完整落版通常保持约 `0.8–1.2s`；这段不再加新运动。

## 六、长片多审阅者策略

多于 24 个语义窗、时长超过约 4 分钟，或已有两类以上重复错误时：

1. 先把语义窗分成 3–4 个连续区间；
2. 每个审阅者只读检查自己的区间，按统一八类问题表输出精确时码、窗口 ID、证据帧和建议；
3. 修复阶段按不重叠文件或不重叠窗口分工，不让多人同时改同一模块；
4. 主制作者统一时间轴、渲染和整片终审；
5. 修复报告不等于通过。新版必须重新抽取同一组锚点帧，并从头到尾 `1×` 播放。

## 七、八类问题报告

每个区间必须明确检查并报告：

1. 无目标的长条、遮罩或装饰线；
2. 证据裁切导致原文、表头或页面身份不全；
3. 应有但缺失或指错目标的红圈、短箭头或光标；
4. 图标与文字、图片与标题、主画面与字幕的碰撞；
5. 相邻窗重复、双曝光或状态重置造成的“像卡住了”；
6. MG 元素未出现、晚到、中途消失或只出空底板；
7. 证据在真实手机尺寸下的可读性；
8. 机械停顿、重复音节、粘字、吞字、错读、突兀接缝和音色跳变。

任意一项未检查，不得写“逐锚点终审通过”。

## 八、审查产物与动态复核

正式长片至少保留到终验结束的审查产物：

1. `anchor manifest`：每个语义窗、每个发声锚点的绝对时码、窗口 ID、当前主张、活动素材和目标状态；
2. `anchor frames`：锚点前后实际成片帧，按连续时段生成联系表，便于逐格核对；
3. `boundary frames`：每个语义窗边界前后帧，成对排列，专门检查错页、空白、双曝光和动画重置；
4. `dynamic samples`：开头、密集截图段、复杂 MG 段、片尾，以及任何异常快切命中的连续视频片段；
5. `audio candidates`：ASR 失配、波形突变、异常静音或创作者指出卡顿的语义句清单。

可先运行：

```bash
python scripts/build_anchor_audit_manifest.py timeline.json audit-manifest.json --reviewers 3
```

硬性规则：

- 联系表用于批量发现问题，最终判定必须回到原尺寸单帧或连续片段；缩略图看不清不等于原图可读，也不等于原图不可读。
- 每个审阅者拿到连续且不重叠的窗口区间，并明确报告八类问题；主制作者必须复核修改后的同一批锚点，不能只收“已修复”的文字结论。
- 对完整成片运行场景变化检测时，筛出相邻显著变化不足约 `0.55s` 的位置，并至少查看变化前 `0.16s`、变化点、变化后 `0.16s` 的连续帧。正常的步骤推进可以放行；错页闪帧、空白、上一页反弹或重复重启动画必须返工。
- 锚点静帧通过不代表运动通过。至少对每种高风险视觉语法播放一个完整动态样本：截图接力、红圈／箭头进入、列表逐项出现、共享对象转场、结果落版。
- 终验报告分别写清“技术检测通过”“逐锚点视觉通过”“ASR 对稿通过”“创作者 1× 听感确认”。没有实际完成哪一项，就不得用其他项目代替或笼统写“全部通过”。
