# 叙事与 MG 动效设计

只在需要写口播、分镜或判断画面形式时读取。

## 三种叙事骨架

### 信息解释

1. 前情或变化：一句话交代上下文。
2. 核心问题：观众为什么要继续看。
3. 关键事实：只保留支持结论的事实。
4. 一个具体例子：把抽象信息变成过程或状态。
5. 边界：哪些是事实、示例、判断或未验证目标。
6. 结论与唯一 CTA。

### 概念说明

1. 先说它不是什么。
2. 用一句普通话解释它是什么。
3. 给一个日常场景。
4. 展示输入、变化和结果。
5. 给出适用条件与限制。
6. 用一句可复述的结论收尾。

### 流程演示

1. 显示用户需求或输入。
2. 拆成 3–7 个动作。
3. 每一步都展示“等待 → 执行 → 完成/返回”。
4. 展示最终回写或结果。
5. 标明真实操作、演示数据或组合设想。
6. 收束为一个判断或下一期方向。

## 场景设计

- 60–120 秒通常使用 6–9 场。
- 每场只回答一个问题；标题直接写结论，不写抽象章节名。
- 主体画面优先使用状态卡、流程节点、对比表、输入框、结果卡和手绘关系线。
- 一屏需要同时比较三个以上字段时用表格；流程有三个以上步骤时用箭头链路；不要为了“高级感”堆无关装饰。
- 画面出现一段时间不等于必须持续运动。信息读完后可以稳定停留。

## 口播—画面双向覆盖

在渲染前为每个场景记录：起止时间、该段口播回答的问题、口播主张、画面主张、关键屏幕文字、覆盖状态。时间轴模板已预留这些字段。

逐场做两个方向的检查：

1. **口播 → 画面**：每个重要口播主张都应有相应的图形、状态、关键词或结果承接，不能整段只放泛化装饰。
2. **画面 → 口播**：场景标题、卡片、流程、对照关系和选择规则中的每个核心信息，都必须在同一场或紧邻口播中得到解释。

可保留没有逐字念出的视觉辅助，只限于同义缩写、编号、图标、状态词和来源/边界标签。下列内容不能只出现在画面里：

- 新的功能或产品能力；
- “什么情况选什么”的判断规则；
- 新步骤、前置条件、限制或风险；
- 新结论、数据或因果关系。

若画面有而口播没有，按顺序选择：删掉该信息；改为与当前口播同义的视觉表达；确有必要时修改口播并请用户补录。不要为了保留已经画好的页面，把未解释的信息硬塞进成片。

场景边界必须跟随完整语义段。比如口播仍在依次定义五个功能时，不能因为视觉页数已满就提前切到“功能怎么选”。

## 动效语义

允许的动效：

- 输入文字逐字出现；
- 卡片进入并稳定落位；
- 等待态切换为完成态；
- 勾选、数字、表格单元格或进度值发生变化；
- 箭头按因果顺序绘制；
- 令牌沿路径移动表示步骤接力；
- 章节切换使用短促擦除、纸张移动或淡入。

避免的动效：

- 无意义漂浮、循环呼吸、随机旋转和持续缩放；
- 所有元素同时弹入；
- 只给静态大图加 Ken Burns 推拉；
- 联系表、拼版或 PPT 翻页冒充独立场景；
- 过场闪白、黑帧或与信息无关的粒子。

## 文案可懂性检查

遇到“对象、执行层、返回值、能力域、编排”等词，先尝试改为观众能执行的动作：

- 对象 → 日历、文档、表格、任务；
- 编排 → 按顺序把几步串起来；
- 返回值 → 系统给回来的结果；
- 执行层 → 真正替你查、建、改的部分；
- 能力域 → 能处理的办公工作类型。

如果创作者本人看不懂一张画面，观众也不会懂。优先删术语，不用更多小字解释术语。

## 风格使用

从用户参考图抽取颜色、形状、字体层级、阴影、图标和留白规则，但不要把一张参考图当作整片静态背景。用户没有视觉参考时，默认使用亲民的信息卡风格：浅色纸张背景、两种主色、一种强调色、粗标题、白色状态卡和少量手绘箭头。
