# 叙事与 MG 动效设计

只在需要写口播、分镜或判断画面形式时读取。

## 三种叙事骨架

### 信息解释

1. 前情或变化：一句话交代上下文。
2. 核心问题：观众为什么要继续看。
3. 关键事实：只保留支持结论的事实。
4. 一个具体例子：把抽象信息变成过程或状态。
5. 边界：哪些是事实、示例、判断或未验证目标。
6. 结论、主行动目标与片尾评论问题。

### 概念说明

1. **问题与价值**：它在解决什么具体问题，为什么观众需要理解它。
2. **普通话定义**：用一句准确的人话说明它是什么，并指出最容易混淆的“它不是什么”。
3. **最小机制**：只保留理解概念所必需的因果链，讲清输入、关键变化与结果；不能只列功能、特征或结论。
4. **贯穿案例**：至少用一个具体案例从输入走到结果，案例要真正映射前面的机制，不能只报一个场景名称后立刻跳走。
5. **边界与误解**：说明一个会影响使用判断的条件、限制或常见误解，不用边角知识稀释主线。
6. **系列关系**：系列内容回扣上一期已经建立的认知，并说明本概念怎样成为下一期的台阶；收官期回收整条认知链。
7. **可复述结论**：用一句观众能够转述给别人的话收尾。

“简明扼要”指删掉不帮助理解的枝节，不是删掉机制、案例和边界。不能用一个未解释的陌生词解释另一个陌生词；新术语若无法在当下顺手讲清，就改成人话、延后或删除。

口播定稿前执行零基础观众复述测试：只依据本期内容，观众是否能回答“它是什么、为什么需要、怎样起作用、能举什么例子、至少有什么边界”。任一项只能复读标题、仍需外部知识或完全答不出来，就说明解释链不完整，须返修后再合成音频。

### 概念内容的媒体组织

认知完整性是内容底线，不是口播目录。优先用下面的观看逻辑把定义、机制、案例和边界编织成一条叙事：

1. 前 3 秒用具体问题、反常识、常见误解或直接后果建立观看理由，不先寒暄、报目录或宣布“今天讲一个概念”。
2. 全片只推进一个核心问题；每一段先回答当前问题，再自然产生下一问，避免并列堆六个知识点。
3. 尽量让一个具体案例贯穿始终：先出现可见冲突或结果，再随着案例推进解释定义、机制和边界。案例不是解释后的附属举例，而是承载解释的主线。
4. 抽象术语出现后立即落回动作、状态或结果；信息密度来自删掉寒暄、重复预告、同义复述和画面可直接读出的内容，不来自连续塞入新名词。
5. 中段至少完成一次认知推进，例如纠正常见误解、揭示真正机制或说明“能做什么不等于保证什么”，让观众获得继续看的新信息。
6. 结尾回扣开头的问题或冲突，用一句可记忆、可转述的结论收束；系列内容再自然承接下一期，不为预告牺牲本期闭环。

### 互动钩子不抢内容钩子

- 前三秒的第一任务是制造观看理由，不是索要互动。先提出信息差、问题或直接后果，再给本期能带来的具体价值。
- 长、密、工具型或可反复查询的内容，在价值承诺后增加一次轻量收藏引导，例如“建议先收藏，真遇到类似任务时可以回来找对应步骤”。不要以“视频很长”开场，也不要没有理由地要求收藏。
- 片尾 CTA 必须放在结论闭环之后。下一期题目未定时，不硬编“下一期讲什么”，改为询问观众还想看当前产品哪个功能，或希望拆哪款工具，并鼓励同时写出最想解决的问题。
- 开头和片尾各只承载一个主要动作。避免“点赞、关注、收藏、转发、评论”连报；互动动作必须与内容价值、回看需求或下一期选择直接相关。
- 标题、封面、前三秒、开头动作钩子、正文结论和片尾问题必须服务同一个受众问题，不能用无关争议骗评论。

定稿前同时执行媒体观看测试：前 3 秒是否值得继续看；信息是否持续推进；案例是否真正承担解释；是否存在教科书式报目录；结尾是否回收开头。知识复述测试和媒体观看测试必须同时通过，不能用“讲得全”掩盖不好看，也不能用“节奏快”掩盖没讲清。

### 情绪不是喊口号

信息型视频也需要情绪变化。定稿前用一句话分别写清：

- **痛点**：观众正在烦什么、怕什么或付出什么重复成本；
- **放大**：如果问题继续存在，会浪费什么、错过什么或制造什么后果；
- **翻转**：观众原来的理解哪里不完整，真正值得看的判断是什么；
- **缓解**：哪条具体证据让观众看到事情可以被改变；
- **回收**：结尾如何回应开头，而不是只报 CTA。

情绪来自具体处境与后果，不靠“震惊、绝了、太强了”等形容词。每 15–30 秒至少发生一次问题升级、证据兑现或认知推进；若整段只能改编号而语气和结构不变，就是目录陈述。

### 流程演示

1. 显示用户需求或输入。
2. 拆成 3–7 个动作。
3. 每一步都展示“等待 → 执行 → 完成/返回”。
4. 展示最终回写或结果。
5. 标明真实操作、演示数据或组合设想。
6. 收束为一个判断或下一期方向。

## 场景设计

- 60–120 秒通常使用 6–9 场。
- 每场只回答一个问题；标题直接写结论，不写抽象章节名。
- 主体画面优先使用状态卡、流程节点、对比表、输入框、结果卡和手绘关系线。
- 一屏需要同时比较三个以上字段时用表格；流程有三个以上步骤时用箭头链路；不要为了“高级感”堆无关装饰。
- 画面出现一段时间不等于必须持续运动。信息读完后可以稳定停留。

### 多案例与功能盘点

- 不默认一项一个场景。先把案例按观众痛点、任务阶段或决策冲突分成 3–5 组，再决定哪些案例完整演示、哪些快速证明。
- 所有案例都可以出现，但镜头权重不必相等。用代表性案例承载完整过程，其余案例用可读证据、对比或递进补全。
- 每组先出现“为什么这会让人难受或低效”，再出现执行变化和结果；不要先报组名再念功能。
- 组与组之间要产生下一问，例如“会生成还不够，能不能按时交付？”让上一段的结果成为下一段的冲突。

## 口播—画面双向覆盖

在渲染前为每个完整语义句记录：实际起止时间、情绪作用、该句回答的问题、口播主张、画面主张、关键屏幕文字、覆盖状态。涉及截图时另记来源、目标区域、证明主张和裁切理由。时间轴模板已预留这些字段。

逐场做两个方向的检查：

1. **口播 → 画面**：每个重要口播主张都应有相应的图形、状态、关键词或结果承接，不能整段只放泛化装饰。
2. **画面 → 口播**：场景标题、卡片、流程、对照关系和选择规则中的每个核心信息，都必须在同一场或紧邻口播中得到解释。

可保留没有逐字念出的视觉辅助，只限于同义缩写、编号、图标、状态词和来源/边界标签。下列内容不能只出现在画面里：

- 新的功能或产品能力；
- “什么情况选什么”的判断规则；
- 新步骤、前置条件、限制或风险；
- 新结论、数据或因果关系。

若画面有而口播没有，按顺序选择：删掉该信息；改为与当前口播同义的视觉表达；确有必要时修改口播并请用户补录。不要为了保留已经画好的页面，把未解释的信息硬塞进成片。

场景边界必须跟随完整语义段。比如口播仍在依次定义五个功能时，不能因为视觉页数已满就提前切到“功能怎么选”。

不得把一个场景时长按图片数量平均切片。场内每次输入、状态改变、截图证据、结果回写和边界提示，都要绑定相应句子的实际发声时间。没有发声锚点的变化只能是非关键辅助动效。

### 官网截图作为证据

每次使用截图前回答四个问题：

1. 当前口播主张是什么？
2. 截图里的哪一处字段、状态或结果能直接证明它？
3. 观众在手机尺寸下是否能完整读懂这处证据？
4. 完整截图、局部裁切、标注框或重绘流程，哪种形式最少损失上下文？

只有第 2、3 项都明确时才做局部放大。放大区应保留必要的标题、行列名、前后状态或操作结果；固定尺寸放大框不能跨不同截图机械复用。若局部证据离开上下文就失去意义，展示完整图并用框线、高亮或遮罩引导视线。

截图布局还必须通过移动端可读性门槛：

- 一张图承担当前主证据时，优先占据约 80%–90% 画面宽度；不能为了同时放装饰卡片而把产品文字缩到无法辨认。
- 同一语义窗恰好需要两张文字型截图时，默认上下排列并让每张图尽可能接近全宽。只有两张图在约 360px 宽的手机预览中仍能直接读懂时，才允许左右并排。
- 三张及以上截图不得做四宫格、联系表或平均分栏。按真实发声锚点逐张全尺寸接力；若本句只是总结关系，就改用 MG 关系图，把截图留到具体步骤中。
- 禁止附加没有独立证明价值的缩略全图、画中画或“放大镜小窗”。需要保留上下文时，直接在同一张大图上做连续镜头推进、框线或局部高亮。
- 公开官网截图不因为“看起来像账号页”就自动打码。只有实际含有未公开的用户资料、凭证、私人通讯或受保护信息时才遮挡；遮挡前先确认不会盖住当前证据。
- 完整图到聚焦区必须连续插值，不能在某个百分比上突然跳成另一种裁切。截图更换也必须先让下一张可识别，再移除上一张。

## 动效语义

允许的动效：

- 输入文字逐字出现；
- 卡片进入并稳定落位；
- 等待态切换为完成态；
- 勾选、数字、表格单元格或进度值发生变化；
- 箭头按因果顺序绘制；
- 令牌沿路径移动表示步骤接力；
- 章节切换使用短促擦除、纸张移动或淡入。

避免的动效：

- 无意义漂浮、循环呼吸、随机旋转和持续缩放；
- 所有元素同时弹入；
- 只给静态大图加 Ken Burns 推拉；
- 联系表、拼版或 PPT 翻页冒充独立场景；
- 过场闪白、黑帧或与信息无关的粒子。

内容切换不得让所有主信息同时消失。除明确章节转场外，交叉切换期间至少有一个完整可读状态；抽查切换前、中、后三帧，若中间帧只剩淡影、空白底或半张裁切内容，即视为卡顿式视觉缺陷。

### 动效导演与变化密度

每个语义窗先写一句“什么对象，从什么状态，经过什么动作，变成什么结果”，再选择动效。模板名称不是导演方案；把四个词塞进四个格子并依次出现，不算完成可视化。

- 流程使用路径绘制、接力令牌和完成状态；选择使用分支、滑杆或条件变化；循环使用回路和当前步骤；跨设备使用真实方向的任务与结果往返；失败切换使用原路径受阻和替代路径生长。
- 同一镜头只保留一个主动作。次要元素可以稳定停留，不靠持续呼吸、漂浮和随机缩放制造“有动效”。
- 连续三个语义窗不得只替换标题、标签和截图而复用同一核心动作。长视频至少建立与任务类型对应的多种运动语法，并在跨案例处改变空间组织或状态变化方式。
- 所有关键变化绑定发声锚点，使用约 0.28–0.62 秒的可读缓动；完成态保留到下一锚点。短促点击反馈可以更快，但任何承载新信息的完整状态若可见不足 0.6 秒，必须改成叠加承接、合并镜头或延长保持。
- 可借鉴 Hyperframes/GSAP 的确定性时间线、连续运动和速度匹配转场，但必须重新按当前品牌网格、证据和语义编排；不得把开源模板直接拼成风格不统一的素材包。

## 文案可懂性检查

遇到“对象、执行层、返回值、能力域、编排”等词，先尝试改为观众能执行的动作：

- 对象 → 日历、文档、表格、任务；
- 编排 → 按顺序把几步串起来；
- 返回值 → 系统给回来的结果；
- 执行层 → 真正替你查、建、改的部分；
- 能力域 → 能处理的办公工作类型。

如果创作者本人看不懂一张画面，观众也不会懂。优先删术语，不用更多小字解释术语。

## 面向观众的媒体文案

口播稿只保留观众需要听到的事实、解释、例子、判断和承接，不朗读制作现场的说明。以下表达通常是制作语言，不是自然口播：

- “画面只是示意”“本图仅为示例”；
- “如图所示”“屏幕上可以看到”“这里我们可以看到”；
- “这张图/这个动画展示了……”；
- “接下来我们看一下这张图”。

资料审计和创作者表达也要分层。`官网没有截图`、`按文字流程还原`、`这张图只能证明什么`、`所以视频里要怎样呈现`属于后台取证、思考或分镜语言，不能进入旁白。来源通常只在标题或开场建立一次；正文由创作者直接讲产品、过程和判断，用“这个例子里、这一次、当时”保留单次案例边界，不逐句充当“官网传话筒”。没有截图时直接用 MG 表达文字步骤；只有缺少结果证据会改变观众判断时，才改写成自然限制。

用户明确补充的个人工作流、选择习惯或创作观点，应在核实能力边界后融入最相关段落，不能留成括号备注或另加一段“我的看法”。组合工作流要分清产品原生能力、自定义接入、外部工具、手动导入和创作者人工调整。尤其不能因为案例只展示到脚本，就断言 AI 不能继续配音、剪辑、渲染或发布；也不能把尚未接通的后续动作说成已经自动完成。

事实边界仍必须保留，但要改写成自然语义。例如把“画面只是示意”改成“不同模型和产品的处理方式可能不同”；把“官网说这是示例耗时”改成“这类任务一般要几分钟，具体还会受内容量和网络影响”。画面可另放一枚不抢主体的“示意”或来源标签。合成前运行 `scripts/check_audience_language.py`，并按 [voiceover-script-acceptance.md](voiceover-script-acceptance.md) 逐句验收；脚本不能替代逐句朗读审校。凡是创作者本人正常聊天时不会说的话，都要重写。

## 版式与关系完整性

- 先确定共同网格和对齐基准，再放标题、卡片、系列角标、字幕以及用户当期明确要求保留的 Logo；同类组件共享高度、圆角、边框、内边距和基线。
- 对齐要同时检查几何结果与视觉结果。文字字框、图标外接框和容器中心线应可量取；导出实际帧后还要缩到手机尺寸目检视觉重心，不能只相信 CSS/Pillow 的居中参数。
- 用户当期明确要求保留的 Logo 胶囊内，图标与文字共享视觉中线，左右留白形成稳定组合；字幕框内的识别点、正文和上下留白共享视觉中线。多行字幕采用同一对齐方式，不随句长漂移。
- 系列角标以及用户当期明确要求保留的 Logo，先建立“容器 → 组合组 → 图标、文字”的单一布局层级。只让组合组在容器内容区内居中，禁止分别给图标和文字写互不关联的绝对横坐标，也禁止靠裁切容器掩盖错位。先用最终字体的实际渲染字形边界和图标可见边界计算组合包围盒，再居中组合包围盒；字体侧边承量、粗细和中文方框造成肉眼偏移时，在数值居中基础上做少量光学补偿。
- 角标修正顺序固定为：确认文字完整且无 `overflow`/蒙版/画布裁切 → 保留稳定图文间距 → 居中整个图文组合 → 比较图标最左可见像素与文字最右可见像素到容器两侧的留白 → 比较组合上下可见像素与容器上下留白 → 只在最后做小幅光学微调。不能通过单独移动文字来制造“差不多居中”，否则不同文案、画幅或缩放时会再次漂移。
- 角标必须按最终输出比例逐版验收，不能把一张角标硬裁复用于 3:4、9:16、4:3 或不同视频场景。导出后裁取角标区域，叠加容器中心线与组合可见包围盒中心线检查；再关闭辅助线，在原尺寸和手机缩略图各目检一次。任一版本出现截字、贴边、图文间距突变、左右留白明显不均、上下偏移或图标居中而文字漂移，均须返修并重渲染。
- 关系线先确定两端节点再绘制。每个箭头都必须终止在可见节点、明确结论或“下一步/继续”的可见标记上；不得穿出画布、指向空白、被遮挡或暗示一个没有出现的后续节点。
- 一屏放不下完整关系时，拆成两场、改变排列或只保留当前讲到的局部链路。不要用被裁断的箭头制造“还有内容”的错觉。
- 正式导出前至少目检开头、每个场景中点、每次转场后第一帧和片尾；重点找越界、遮挡、裁切、错行、对齐漂移、未闭合连接和没有解释的残留标签。
- 场景页码、镜头序号、英文 kicker、模板分栏名和极小脚注必须能回答“它具体帮助观众理解了什么”。若答案只是方便制作、填补留白或制造模板感，就删除。不要把内部镜头进度伪装成栏目包装。

## 风格使用

从用户参考图抽取颜色、形状、字体层级、阴影、图标和留白规则，但不要把一张参考图当作整片静态背景。用户没有视觉参考时，默认使用亲民的信息卡风格：浅色纸张背景、两种主色、一种强调色、粗标题、白色状态卡和少量手绘箭头。
